# kagiboy cartridge firmware (RP2350)

MIT. Work in progress: the board isn't built yet.

| Crate | What | Status |
|---|---|---|
| `core/` (`kagiboy-core`) | The wallet logic: the Game Boy mailbox, PIN and wipe rules, BIP-39 words, Solana and EVM keys, transaction decoding and signing, swaps, pairing, QR codes; the bus-side mailbox (`bus.rs`) and the stored-wallet format (`persist.rs`). `no_std`, so the same code runs on the RP2350 and in host tests | done, matches the browser chip byte for byte |
| `cart/` (`kagiboy-cart`) | The firmware for the board in `hardware/cart` (Embassy, RP2350B at 150 MHz): serves the wallet ROM and the mailbox on the Game Boy bus with PIO + DMA, runs `kagiboy-core` | bus, mailbox and wallet done, builds; SE050, phone link (ESP32-C3) and LIS3DH next |

## How the bus is served (`cart/`)
- `gb_read` (PIO0 SM0) answers every ROM read from a 32 KB image in SRAM: two chained DMA channels turn the address it
  pushes into the byte at that address and hand it back, and it drives D0-D7 in time. The chip's half of the
  mailbox sits in that image at 0x7F00, where the hardware build of the ROM reads it.
- `gb_write` (PIO0 SM1) samples every write cycle. The board has no /WR line, so a write is a cycle with /RD high; a
  third DMA channel streams the samples into a 32 KB ring, so nothing is lost while the CPU signs or writes flash.
- The CPU drains the ring into the Game Boy's half of the mailbox and runs the wallet.
- `cart/pio/*.pio` are generated by `hardware/sim/emit-pio.ts` from the cycle-level simulation's own design, which
  passes on the real ROM's bus traffic with this board's pin map (83 ns of margin to the early latch at 150 MHz,
  0 contention, hold or write errors; see `docs/hardware-sim.md`). Two independent assemblers (pio-parser, which the
  firmware uses, and Adafruit's pioasm) give identical instruction words.

## Not done yet
- **SE050:** keys and the PIN move into the secure element. Until then `FlashStore` keeps the wallet in flash:
  development only.
- **Phone link:** the ESP32-C3 over SPI (the WiFi cart's protocol v1), with Bluetooth LE on the ESP side.
- **LIS3DH** for shake entropy and tilt.
- Running on hardware: the board isn't built.

## The browser chip is the reference
`web/src/chip/chip.ts` is the chip the ROM is developed and tested against. `kagiboy-core` is its port, and is held to it:
- `web/scripts/chip-vectors.ts` drives the browser chip through full sessions and records every mailbox reply,
  every phone-side refusal, every pairing code and every signature, with a seeded random stream and a fixed clock
  (`core/tests/vectors/*.json`).
- `core/tests/vectors.rs` replays them against the Rust chip with the same random bytes and requires identical
  bytes: replies, the chip's half of the mailbox after every command, refusal texts, signed transactions.
- The networks, swap tokens and fees are generated from the TypeScript tables (`web/scripts/chip-tables.ts` ->
  `core/src/tables.rs`), so the two can't drift.

Run (from `web/`, then here):
```sh
pnpm exec tsx scripts/chip-vectors.ts ../firmware/rp2350/core/tests/vectors
pnpm exec tsx scripts/chip-tables.ts
cd ../firmware/rp2350 && cargo test -p kagiboy-core --release
cargo build -p kagiboy-core --release --target thumbv8m.main-none-eabihf
cd cart && cargo build --release        # the firmware; needs rom/build/wallet-hw.gb (make hw in rom/)
```

Differences from the browser chip, by design:
- Time comes from the phone (the cartridge has no clock): the 60 s pairing lapse and swap deadlines use it.
- Keys are derived on the chip as in the browser; on the cartridge they will move into the SE050 (next step).
